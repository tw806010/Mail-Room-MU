## 1. 系統簡介

本系統供學校收發室登記每日收到的掛號函件、包裹與快遞，並管理「待領取／已領取」狀態，同時可產出簽收清冊、收件公告圖片與 Excel 報表。

**主要特色**

| 功能 | 說明 |
|---|---|
| 條碼掃描 | 編號欄支援鍵盤輸入或 USB 條碼掃描槍刷入 |
| 自動時間戳記 | 登記送出時自動記錄「資料建立日期和時間」 |
| 一鍵簽收 | 記錄簽收／代領人與領取時間 |
| 簽收表 | 一鍵產生直式 A4 親筆簽收清冊 |
| 收件摘要圖 | 產生高畫質 PNG，可貼到 LINE 群組或電子布告欄 |
| 資料保全 | 不提供刪除功能；完整備份／還原；資料檢查；多分頁保護 |
| 離線可用 | 資料存在本機瀏覽器（LocalStorage），不上傳任何伺服器 |

## 2. 快速開始

### 2.1 開啟系統

直接以滑鼠**雙擊資料夾中的 `index.html`**，使用 Chrome、Edge 或其他現代瀏覽器開啟即可。

> 建議使用 **Chrome 或 Edge**。請固定使用「同一台電腦、同一個瀏覽器、同一個開啟方式」，因為資料儲存在該瀏覽器中（見 [FAQ](#8-常見問題-faq)）。

### 2.2 檔案組成

```
├── index.html          版面與所有彈跳視窗
├── app.js              介面與業務邏輯
├── backup-core.js      資料安全核心（備份／還原／檢查，純邏輯）
├── style.css           孔雀綠主題與列印樣式
├── CLAUDE.md           專案開發筆記
├── README.md           本說明書
└── tests/              自動化測試
```

請將整個資料夾完整保留，**不要單獨搬動 `index.html`**。

### 2.3 第一次使用

清單為空時，可點選畫面中的「**載入示範測試資料**」載入 6 筆範例資料熟悉操作。
⚠️ 因為系統沒有刪除功能，示範資料寫入後**無法刪除**，正式使用前請確認是否需要載入。

由上而下依序為：

- 新登記的紀錄排在清單最前面。

## 4. 日常作業流程

### 4.1 登記新信件／包裹

於「信件／包裹登記作業」填寫表單（標示 `*` 為必填）：

| 欄位 | 必填 | 說明 |
|---|:-:|---|
| 掛號函件／包裹編號 | ✅ | 直接輸入，或用條碼掃描槍刷入（掃描槍最後送出的 Enter 會自動跳到下一欄） |
| 郵件類型 | ✅ | 下拉選單：掛號函件、掛號包裹、快遞包裹、國際函件、國際包裹、限時掛號函件 |
| 郵件經手人 | ✅ | 下拉選單：名單由「設定」維護（預設「經手人A」「經手人B」），另有**其他**。選「其他」會展開欄位讓您手動輸入姓名 |
| 寄件人 | ✅ | 例：教育部、勞動部、某公司、個人 |
| 收件人 | ✅ | 例：王小明 老師 |
| 收件人所屬單位 | ✅ | **純手動輸入**，例：護理系、總務處、教務處 |
| 備註說明 | | 選填，例：放置於總務處專屬箱、貴重、生鮮冷藏 |

填寫完成後按「**確認登記並送出 (Enter)**」。系統會自動記錄建立時間，並更新統計卡片。
按「**清除重新填寫**」可清空表單。

**連續登打小幫手**

- **記住上次選擇**：存檔後，下一筆自動沿用上一筆的「郵件經手人」與「郵件類型」，重新整理頁面後也會記得（存在本機）。
- **收件人自動完成**：輸入收件人時，會從過去登記過的資料列出建議（姓名包含輸入文字即可，例如打「王」列出所有姓王的人）。用 ↑↓ 選擇、Enter 確認、Esc 關閉；選定後自動帶入該收件人上一次登記的單位，仍可手動修改。
- **單號檢查**：送出前會去除單號前後空白，並檢查只含英數字與連字號、長度合理（預設 6～30 字元）。有問題時，提醒文字顯示在單號欄下方，不會跳出視窗。規則集中在 `app.js` 的 `TRACKING_RULES`，可依實際單號格式調整。

> **重複編號提醒**：若「同一天已登記過相同編號」，或已存在「相同編號且待領取」的紀錄，單號欄下方會顯示提醒與「仍要存檔」按鈕（不會跳出視窗）。確認要再登記一次時，按「仍要存檔」，或在表單內再送出（Enter）一次即可。

### 4.2 搜尋與篩選

位於清單上方的篩選列，可同時組合使用：

- **搜尋框**：即時搜尋編號、收件人、寄件人、所屬單位。
- **郵件類型**：全部或指定類型。
- **領取狀態**：全部／🔴 待領取／🟢 已領取。
- **日期**：全部日期／僅今日／近 7 天／近 30 天。

下方會顯示「顯示 N 筆紀錄」。

### 4.3 簽收領取與取消簽收

1. 在該筆紀錄的「操作」欄點「**🖊️ 簽收領取**」。
2. 於彈出視窗確認編號、收件人、單位，並填入「**簽收／代領人姓名**」（預設為收件人本人，若他人代領請改填代領人）。
3. 按「**確認完成簽收**」，狀態變為🟢已領取，並記錄簽收人與領取時間。

若誤按簽收，已領取的紀錄會顯示「**取消簽收**」按鈕，可還原為待領取。

### 4.4 修改紀錄

點選「**✏️ 修改**」開啟彈跳視窗，可修正：編號、郵件類型、經手人、寄件人、收件人、單位、備註、領取狀態（待領取／已領取）與實際簽收／代領人。按「儲存修改」生效。

> 🔒 **本系統刻意不提供刪除功能**，以防行政登記紀錄被誤刪。登記錯誤請用「修改」更正。
> 每次修改、簽收、取消簽收都會在該筆紀錄留下異動歷程（`updatedAt`、`history`）。

## 5. 輸出與報表

### 5.1 生成簽收表（直式 A4）

供現場親筆簽名及留存備查。點工具列「**生成簽收表**」開啟預覽：

| 選項 | 說明 |
|---|---|
| 篩選日期 | 僅今天（預設）／昨天／自訂特定日期／全部歷史郵件 |
| 領取狀態 | 僅待領取（預設，供現場簽名）／全部（含已簽收備查） |
| 排序依據 | 依建立時間由早到晚（預設）或由晚到早 |
| 簽名欄高度 | 寬敞手寫 56px（預設）／特大簽名 72px／標準緊湊 44px |

**表格欄位順序固定**：郵件類型 ➔ 寄件人 ➔ 收件人 ➔ 收件人單位 ➔ 編號 ➔ 簽名欄。

- 「編號」是依當日建立時間產生的**流水序號**（最早登記者為 1；切換排序方向時，序號仍代表登記先後）。
- 頁首自動帶出簽收日期與件數；頁尾預留**經手人**與**主管**簽核欄。

確認預覽後按「**立即列印 A4 簽收表 (Ctrl + P)**」。列印時請選擇 **A4、直向**。

### 5.2 儲存收件摘要（PNG 圖片）

適合轉貼至 LINE 群組、社群或電子布告欄，通知收件人來領取。點工具列「**儲存收件摘要**」：

| 選項 | 說明 |
|---|---|
| 日期篩選 | 僅今天（預設）／昨天／自訂特定日期／全部歷史郵件 |
| 領取狀態 | 僅待領取（預設）／全部（含已簽收） |
| 排序依據 | 依建立時間由早到晚（預設）或由晚到早 |

- 圖片包含三大欄位：**收件人姓名、收件人單位、郵件類型**。
- 圖片高度會依筆數**自動伸縮**，確保每筆都清晰可見（2 倍解析度）。
- **每張圖最多 40 筆**，超過會自動分頁，以「◀ 上一頁／下一頁 ▶」切換，每頁各自下載。
- 底部「**製表人**」自動取篩選結果中經手次數最多者（例如「經手人A」居多則顯示「製表人：經手人A」）。
- 按「**下載圖片 (PNG)**」存檔（檔名如 `美和科技大學_收件摘要_日期.png`），或按「**複製圖片**」後直接貼到 LINE、Word 或信件。

### 5.3 匯出 CSV

按「**匯出 CSV**」下載 `美和科技大學收發室信件登記清冊_日期.csv`，內含 UTF-8 BOM，**Excel 開啟不會亂碼**。

欄位：序號、狀態、掛號函件／包裹編號、郵件類型、收件人、收件人所屬單位、寄件人、郵件經手人、資料建立日期和時間、簽收人、簽收時間、備註。
（匯出時對以 `=`、`+`、`-`、`@` 開頭的內容做了防護，避免試算表公式注入。）

### 5.4 列印清冊

按「**列印清冊**」列印目前清單顯示的內容（會套用目前的搜尋與篩選結果），已內建最佳化列印樣式與抬頭。

## 6. 資料備份與還原

> ⚠️ 資料存放在瀏覽器的 LocalStorage。若執行「清除瀏覽資料」、更換電腦或重灌系統，**資料可能消失**。請務必定期備份。

**建議**：每週（或至少每月）按一次「完整備份」，將 `.json` 檔存放到隨身碟或公務資料夾。

### 6.1 完整備份

按「**完整備份**」會下載 `美和科技大學收發室_系統完整備份_日期.json`，包含所有歷史郵件紀錄。

### 6.2 還原備份

按「**還原備份**」並選擇 `.json` 備份檔，流程如下：

1. **備份驗證**：檢查格式、版本、筆數、必要欄位。
2. **還原預覽**：顯示備份檔名、備份時間、備份筆數、目前現存筆數，以及逐筆差異比較。
3. **選擇還原方式**：
   - **與現有資料合併**（預設）：保留現有資料，補入未重複的紀錄（以 ID 或「編號＋建立時間」判斷重複）。
   - **完全覆蓋**：清空目前資料，完全以備份檔取代。
4. **確認**：按「開始還原」並確認提示。
5. 系統**自動下載「還原前自動備份」**檔（請確認瀏覽器已成功儲存）。
6. **完全覆蓋**須再做一次**二次確認**。
7. **寫入**後系統**重新讀取驗證**；若驗證失敗，**自動回復為原本資料**。

備份中缺少 ID 或 ID 重複的紀錄，還原時會自動補上唯一 ID（預覽會顯示「將自動補上 N 筆 ID」），原始備份檔不會被修改。

### 6.3 備份提醒列

清單上方的提醒列會顯示「最後匯出時間」與「尚未備份的變更數」，並提供「**立即備份**」按鈕：

- 🟢 正常：近期已備份。
- 🟡 提醒：距上次備份超過 24 小時。
- 🔴 警示：**從未備份過**且已有資料。

### 6.4 資料檢查

按「**資料檢查**」會**唯讀**檢查：ID、編號、日期、必要欄位、領取狀態與重複紀錄，並產生報告。
此功能**不會修改、刪除或自動修復任何資料**；發現問題請用「修改」功能逐筆確認。

### 6.5 儲存失敗／資料損毀警示

- **儲存失敗**（例如瀏覽器空間已滿）：畫面會持續顯示警示，並提供「**緊急匯出備份**」。此時畫面上的內容永遠等於已成功儲存的狀態，失敗的變更會一併還原。
- **資料損毀**：若讀到無法解析的資料，系統會先把原文另存（最多保留 3 份）並提供下載（檔名 `美和科技大學收發室_損毀資料原文_*.txt`），避免被之後的儲存覆蓋。
- **多分頁保護**：若同時在兩個分頁開啟系統，另一分頁修改後，本分頁會自動重新載入；若儲存被拒（資料已被他處更新）會顯示「重新載入」警示。**請避免同時開多個分頁操作。**

## 7. 資料保全設計

- 🔒 **不設刪除按鈕**，防止公務紀錄誤刪。
- ✏️ 所有變更皆有異動歷程（`updatedAt`、`history`）。
- 💾 備份／還原流程具驗證、預覽、自動備份、二次確認、寫入後驗證與自動回復。
- 🛡️ 畫面輸出一律跳脫（`escapeHtml`）防止 XSS；CSV 匯出具公式注入防護。
- 📴 資料只存在本機，不會連線上傳（僅「Google Fonts 字型」需連網，離線時自動退回系統字型，不影響功能）。

## 8. 常見問題 FAQ

**Q1. 資料存在哪裡？關掉瀏覽器會不見嗎？**
存在瀏覽器 LocalStorage（鍵名 `meiho_mailroom_records_v1`），關閉或重新整理**不會**消失。但清除瀏覽資料會清空，請定期備份。

**Q2. 換了瀏覽器或電腦，資料不見了？**
LocalStorage 是各瀏覽器獨立的。請在舊環境「完整備份」，再到新環境「還原備份」。

**Q3. 同一個 `index.html`，用「雙擊開啟」與「從其他路徑開啟」資料會不同？**
是的。瀏覽器依網址（來源）分開儲存。請固定使用同一個路徑與方式開啟。

**Q4. 登記錯了怎麼辦？沒有刪除鈕。**
請用「✏️ 修改」更正內容。這是為了保全公務資料的刻意設計。

**Q5. 簽收人簽錯了／誤按簽收？**
可按「取消簽收」恢復待領取，或用「修改」直接調整簽收人。

**Q6. 條碼掃描槍刷入後沒反應？**
請先點一下「掛號函件／包裹編號」欄位使游標在其中，再刷入；確認掃描槍設定為鍵盤模式（HID）並於結尾送出 Enter。

**Q7. 摘要圖片下載／複製失敗？**
「複製圖片」需要瀏覽器支援剪貼簿寫入；若失敗，請改用「下載圖片 (PNG)」。

**Q8. 還原時為什麼會多下載一個檔案？**
這是「還原前自動備份」，萬一還原結果不符預期，可用它回到還原前的狀態，請勿刪除。

**Q9. 如何新增經手人？**
按清單工具列的「**設定**」，在「經手人名單」輸入姓名按 Enter 即可新增；也能刪除（過去的紀錄不受影響）。名單存在本機瀏覽器，並包含在「完整備份」中。第一次使用新版時，名單會自動由既有紀錄的經手人欄位產生。

## 9. 系統維護與開發筆記

### 技術架構

純前端（HTML + CSS + JavaScript），無伺服器、無建置流程。

| 檔案 | 職責 |
|---|---|
| `index.html` | 版面與所有 Modal |
| `app.js` | 介面與業務邏輯 |
| `backup-core.js` | 資料安全核心（全域 `MailBackupCore`；純邏輯、不碰 DOM、可獨立測試） |
| `style.css` | 孔雀綠主題與列印樣式 |

### 集中設定（`app.js` 頂端）

```js
const DEFAULT_HANDLERS = ['經手人A', '經手人B'];  // 全新安裝且無紀錄時的預設名單
const SUMMARY_PAGE_SIZE = 40;                     // 收件摘要圖每張最多筆數
```

經手人名單不寫在程式碼中，而是存在本機（鍵名 `meiho_mailroom_handlers_v1`），由「設定」介面維護。

郵件類型（`MAIL_TYPES`）沿用 `backup-core.js` 的設定。下拉選單由程式產生，HTML 不需重複修改。

### 儲存與資料格式

- LocalStorage 鍵名：`meiho_mailroom_records_v1`；新紀錄以 `unshift` 置頂。
- 備份 JSON 格式版本：`"1.0"`。**正式資料結構與備份格式不可任意變更。**
- 輔助鍵（不屬於正式資料）：
  - `meiho_mailroom_backup_meta_v1`：最後匯出時間、未備份變更數。
  - `meiho_mailroom_corrupt_stash_v1`：損毀原文保存（最多 3 份）。
  - `meiho_mailroom_prefs_v1`：上次使用的經手人與郵件類型（操作習慣，不含在備份內）。
  - `meiho_mailroom_handlers_v1`：經手人名單（字串陣列）。完整備份檔多一個選填欄位 `handlers`，舊備份沒有此欄位仍可還原。
- 紀錄欄位：`id`、`trackingNo`、`mailType`、`sender`、`recipient`、`department`、`handler`、`remark`、`createdAt`（`YYYY-MM-DD HH:mm:ss`）、`status`（`PENDING`／`RECEIVED`）、`receivedAt`、`receivedSigner`；選填：`updatedAt`、`history`。

### 自動化測試

- **瀏覽器版**（免安裝 Node）：雙擊 `tests/test-runner.html`，標題顯示 `PASS` 即通過（目前 115 項）。全部使用模擬資料與假 storage，不會動到真實 localStorage。
- **Node 版**：

```bash
node --test "tests/*.node.test.js"
```

修改 `backup-core.js` 後務必重跑測試。

### 開發注意事項

- **不要加入刪除功能**（刻意不設置）。
- 表格按鈕以 `data-action`／`data-id` ＋事件委派處理，不使用 inline `onclick`。
- 簽收表列印透過 `body.printing-a4-sign-sheet` 切換樣式，`afterprint` 事件會還原。

## 10. 已知限制

1. **近 7／30 天篩選邊界日可能差一天**：以 UTC 解析日期與本地時間相減所致。
2. **標頭時鐘初始文字為靜態範例**：載入後立即由 JS 覆蓋，不影響功能。
3. **外部字型需連網**：離線時退回系統字型（如微軟正黑體），Canvas 圖片仍可正常繪製。
4. 資料僅存於單一瀏覽器，**不會自動跨電腦同步**，請依第 6 章備份。
